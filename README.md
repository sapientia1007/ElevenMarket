## [ElevenMarket] 대용량 처리를 고려한 경매 기반 이커머스 구현

- 해당 프로젝트는 **11번가를 모티브로 한 쇼핑몰에 실시간 경매 입찰 기능을 통합**한 이커머스 플랫폼 구현을 목표로 진행
- 핵심 기능인 **주문 및 경매 입찰 서비스의 동시성 문제**를 안정적으로 해결하고,  
대용량 데이터를 효율적으로 처리하여 **시스템의 확장성 및 데이터 무결성**을 확보하는 데 중점

---

### 주요 기능 구현

| 카테고리 | 주요 기능 | 상세 설명 |
| --- | --- | --- |
| **상품 및 구매** | 사용자 로그인, 상품 등록/관리, 일반 상품 구매 | 기본적인 이커머스 운영 기능 제공 |
| **경매 시스템** | 경매 상품 등록, 실시간 입찰, 낙찰 후 결제 처리 | 실시간 입찰 시스템을 통해 경매의 동시성 확보 |

### ⚙️ 핵심 기술 구현 및 동시성/확장성 전략

### 1. 주문 서비스 동시성 제어: 비관적 락(Pessimistic Lock) 적용

- **구현 방법:** JPA의 `비관적 락(Pessimistic Lock)`을 활용하여 동시 주문 시 발생하는 재고 불일치 문제를 방지
    - 트랜잭션 내부에서 상품 조회 시 락을 선점하여, 해당 트랜잭션이 완료될 때까지 다른 동시 접근을 원천적으로 차단하는 방식으로 데이터 무결성을 확보
- **검증:** `ExecutorService`와 `CountDownLatch`를 활용한 **동시성 테스트**를 통해 락 적용 후 재고 무결성이 안정적으로 보장됨을 확인

### 2. 경매 입찰 동시성 제어: 레디스 기반 분산 락 (Redisson 활용)

- **레디스 선정 이유:** 애플리케이션 인스턴스가 여러 대인 분산 환경에서 JVM내 Synchronized의 한계를 극복하기 위해 **레디스(Redis) 기반의 분산 락**을 선택
- **`Redisson` 활용:** 경매 입찰과 같이 짧은 시간에 대규모 트래픽이 몰리는 상황에서 `Pub/Sub` 기반으로
  락 해제 알림을 받아 효율적으로 재시도하는 `Redisson` 라이브러리를 도입 ➔ 이를 통해 락 획득, TTL 기반 자동 해제, 락 연장 등 복잡한 분산 락 로직을 안정적으로 처리

### 3. 대용량 데이터 삭제 전략: 배치 및 청크 단위 삭제

- **문제 인식:** 연관 관계가 복잡한 대량 데이터를 한 번에 삭제할 경우 발생하는 **트랜잭션 타임아웃 및 DB 부하 위험**을 인지
- **해결 방법:** *Soft Delete* 후 1주일이 지난 데이터를 **청크(Pageable) 단위로 나누어 처리**하는 스케줄러 기반의 배치 삭제 로직을 구현
    - **벌크 삭제:** `입찰 → 경매 → 상품` 순서로 ID 목록을 추출하고, **벌크 Delete 쿼리**를 활용해 연관 데이터를 한 번에 효율적으로 삭제

### 4. 메인페이지 랜덤 상품 페이징: 레디스 캐싱 기반 구현

- **문제 인식:** MySQL의 `ORDER BY RAND()`는 데이터 증가에 따라 **DB 부하**를 유발하는 실무 지양 방식임을 확인하고,   
이를 해결할 **캐시(Cache) 기반 접근법**으로 전환
- **해결 방법:**
    1. **레디스 ID 동기화:** 활성 상품 ID 목록을 주기적인 스케줄러를 통해 **레디스 Set 타입에 동기화**하여 관리
    2. **서버 랜덤 처리:** 요청 시 레디스에서 전체 ID 집합을 가져와 Java 서버 메모리 내에서 `Collections.shuffle()` 을 사용하여 랜덤 순서를 생성
- **효과:** DB에 랜덤 정렬 쿼리를 사용하지 않고 **레디스와 서버 CPU 연산을 분리**하여
DB 부하를 최소화하고 대용량 환경에서도 **안정적인 랜덤성과 응답 속도**를 확보
